## 1. 叙事结构：为什么它不像硬广

核心观点先于产品：**「装完 Codex，这 5 个 Skill 能直接开挂」**。观众先被结果抓住，再进入五个证据章节。每个章节都是同一套句法：

> 一个具体痛点 → 可核对的数字或前后对比 → 把 Skill 当作解法带出来 → 用一句利益收束

产品不是被「介绍」的，而是被「用证据推到台前」的。结尾也不是关注、点赞或下载 CTA，而是把观众自己的目标说完再落一句「这个 Skill 必装」。

| --- | --- | --- | --- |
| 钩子 | 0:00–0:02.5 | 观点 + 利益 | 5 个神级 Skill，装完 Codex 直接开挂 |
| ① Caveman | 0:02.5–0:27.2 | 省钱 / 省 Token | 同样问题 63 Token → 20 Token，GitHub 11 万星 |
| ② Taste Skill | 0:27.2–0:48.9 | 审美 / 去 AI 味 | 247 个站点 → 20 种路线，拒绝套模板 |
| ③ Playwright | 0:48.9–1:19.4 | 效率 / 可复现 | 9.8 万星，15x，竞品调研全流程代劳 |

对 Sphere 策划的直接启示：先写一句能站住的核心观点（例如「金融人做 IP，不必会拍会写会剪」或「以前一个团队几小时，现在 15 分钟出一条」），再用选题、写稿、数字分身、声音、合规辅助检查当证据，而不是按功能菜单报菜名。

## 7. 可复制的制作规范

下面的数值都可以直接进 ffmpeg 滤镜或 HTML/CSS 渲染（建议用 1920×1080 做图层，最后再套 9:16 安全框或重排）。缓动若无特殊说明，用 CSS `cubic-bezier(0.25, 0.10, 0.25, 1.00)` 或 ffmpeg `ease` 近似（in-out）。

### 7.1 画布与时间

- 参考片画布：`1920×1080`，`30 fps`，视频编码建议 H.264 yuv420p。
- 小红书成片画布：`1080×1920`。把横屏规范按「高度百分比」迁移，不要把 62 px 字原样搬到竖屏（否则会偏小）；竖屏字幕字高用画幅高度的 4.0%–4.5%，即 **76–86 px**，仍单行居中，底边距 80–110 px，给蒲公英标签和互动栏留空。
- 目标片长：本参考是 2:02。Sphere 商单建议 60–90 秒，章节减到 3–4 个，单镜仍保持 2.5–3 秒中位，快切段落可到 0.4–0.8 秒。
- 口播语速：280–320 汉字/分钟，一句一字幕，不要两个意思挤在同一行。

### 7.2 颜色

| 名称 | Hex | 用法 |
| --- | --- | --- |
| 白字 | `#FFFFFF` | 字幕填充、钩子标题、章节标题 |
| 黑描边 | `#000000` | 字幕描边 |
| 字幕浅底 | `#D0D0D0` 或 `rgba(0,0,0,0.20)` | 仅叠在浅色界面上 |
| 红标记 | `#E0000E`（实测中位约 `rgb(224,0,14)`） | 框、圈、箭头 |
| 黑板深底 | `#1A191E` 到 `#37363B` 的纹理，不要纯黑平涂 | 章节卡 |
| 钩子底 | `#0A0A0A` + 网格线 `#1C1C1C`–`#2A2A2A` | 开场 |
| 对比条蓝 | `#3AA0FF` 左右 | Computer Use 短条 |
| 对比条橙 | `#F5A623` 左右 | 胜出项长条 |
| 时间线强调 | `#F5D76A` | 轨道黄框 |

### 7.3 字幕（HTML 示例规格）

```
画布 1920×1080
font-family: "Source Han Sans SC Heavy", "Noto Sans SC Black", sans-serif;
font-weight: 900;
font-size: 62px;          /* 可视高度约 60–62px */
color: #FFFFFF;
-webkit-text-stroke: 7px #000000;  /* 或 paint-order: stroke fill，描边 6–8px */
paint-order: stroke fill;
letter-spacing: 0.02em;
text-align: center;
position: absolute;
left: 50%;
bottom: 45px;
transform: translateX(-50%);
line-height: 1.0;
padding: 14px 24px;       /* 仅浅色底时加灰底 */
background: rgba(208,208,208,0.92);
border-radius: 12px;
最大宽度: 1600px
一行不超过 16–18 个汉字
出现: opacity 0→1, 80–120ms, 无位移或仅 6px 上移
切走: 硬切或 80ms 淡出
```

竖屏把 `font-size` 改为 80px 左右，`bottom` 改为 96px，`-webkit-text-stroke` 仍保持字号的 11%–13%。

### 7.4 钩子标题

- 两行，水平垂直都居中偏上；第 1 行字高 136px（画幅高的 12.6%），第 2 行 148px（13.7%），行距 130px。
- 字色 `#FFFFFF`，可加极弱的上下金属渐变（顶 `#FFFFFF`，底 `#E8E8E8`）。
- 时间轴：0.00–0.20 只播故障色块；0.20–0.50 标题带 RGB 偏移（R 层 x-8px，B 层 x+8px，0.3s 回到重合）；0.50–2.50 持住；2.50 硬切章节卡。
- 网格：背景 `#0A0A0A`，网格间距约 40px，线宽 1px，颜色 `#222222`。

ffmpeg 故障可近似为：

```
# 0.20–0.50 色散（示意，需按时间切段后 overlay）
rgbashift=rh=-8:bh=8,eq=contrast=1.05
```

### 7.5 章节卡

- 全屏黑板纹理（拍摄或叠加噪点+粉笔擦痕，对比不要太干净）。
- 标题偏下居中：字高 132px，垂直中心约 y=725（1080 的 67%）。
- 字体用带缺口的 stencil / 粉笔风格，色 `#FEFEFE`。
- 时长 1.2–1.5 秒。进入：硬切，或 0.25 秒内字母从残缺到完整（遮罩从左到右 200–300ms）。
- 离开：硬切，或接 0.3s 径向模糊再进下一镜。
- 五张卡只用「序号 + 名称」，不要写成句子。

### 7.6 效果清单与做法

**1）缓慢推镜（静态截图）**

- 素材先按中心裁到 1920×1080 的 108%–116%，再在 4–8 秒内从 100% 放到 108%–116%，锚点在画面视觉中心（略偏上，避开字幕）。
- 缓动 in-out。不要每个镜头都推，高质感静帧、对比卡、成品站适用；正在滚动的录屏不要叠加推镜。

```
# 6 秒从 1.00 推到 1.12，中心缩放
zoompan=z='1+0.12*(on/180)':x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)-20':d=180:s=1920x1080:fps=30
```

更细的 ease 建议在 HTML/CSS `transform: scale()` + `transition-timing-function` 里做，再整段录屏。

**2）径向缩放模糊转场（0.30–0.45s）**

- 前一镜（章节卡或黑场）在 8–10 帧内 `scale 1.0→1.25` 同时 `spinblur` / `zoomblur` 强度 0→20；后一镜反向 1.15→1.00 解模糊。
- 可叠加 1 帧 80% 白闪，但不要每段都闪。

**3）三维翻页（0.40s）**

- HTML：后一页 `rotateY(-90deg)→0`，前一页 `0→90deg`，`perspective: 1400px`，时长 400ms，`cubic-bezier(0.2, 0.7, 0.2, 1)`。
- 用来换「同一产品的下一处证据」，不要用在章节之间（章节之间保持硬切，节奏才清楚）。

**4）红框 / 红圈 / 红箭头**

- 框：`border: 4px solid #E0000E; border-radius: 10px;` 内边距 8–12px，不要填充。出现时 120–160ms 从 92% 缩放到 100%，或描边从 0 画到闭合（200ms）。
- 圈：正圆或椭圆，同样 4px 描边，圈住单个词或数字，直径比目标大约 12–20px。
- 箭头：同色实心三角 + 直线，从框外 40–80px 处指向目标，可 150ms 滑入。
- 同一屏最多 1 个主标记，避免满屏红。

**5）界面录屏规范**

- 先把界面切到简体（Sphere 按已确认的设置）。
- 保留系统光标，点击前停 0.3–0.5 秒让观众看清目标。
- 滚动速度跟口播：一句对应一处界面变化，不要无声狂滚。
- 关键数字出现后加红框，再把该数字写进字幕。
- 产品界面累计出场 ≥ 5 秒（brief 硬性要求），建议单次连续展示 5–8 秒，不要碎成很多 0.5 秒。

**6）左右 / 前后对比卡**

- 左右分栏或上下胶囊条。败方在左/上、短、冷色；胜方在右/下、长、暖色或品牌色。
- 数字要同时出现在画面和字幕里（「以前一个团队，几小时」VS「Sphere 15 分钟/条」）。
- 不要用跳动计数器凑热闹，静态大数字更干净，也更像本参考。

**7）巨型半透明主题字**

- 单行，字高约画幅高度的 10%–12%（横屏约 110–130px），`color: rgba(255,255,255,0.80)`，可加 2px 黑描边。
- 放在画面垂直中区，避开产品 Logo 和底栏字幕。只在章节「亮出名字」时用一次。

**8）快切展示自动化**

- 同一流程的 5–8 个不同滚动位置，镜长 0.35–0.80 秒，全部硬切，BGM 不要降，可加轻微 whoosh。
- 适用于 Sphere「15 分钟出片」的压缩过程，但不要把创建数字分身这种需要看清步骤的模块也切碎。

**9）多宫格铺开**

- 深色网格底，单元从 1 张加到 6–9 张，每 0.4–0.6 秒出现一块，ease-out。用来表现「多版本 / 批量」，对应 Hypit 段，也可借来表现「一条内容多平台分发」（若 brief 允许且产品确实有此能力）。

**10）音效与 BGM**

- BGM：中速电子，音量压在人声下约 -12 到 -18 LUFS 相对差；金融账号不要用过于娱乐的 drop。
- SFX：钩子故障 1 次；章节卡 hit 1 次；翻页 whoosh；红框出现时可加极短 tick。不要句句加音效。
- 本商单配音按已定方案用剪映 AI 配音，BGM 用 Pixabay；二者都要在成片里标清来源，以配合「含 AI 生成内容」标识。

### 7.7 结构模板（给 Sphere 脚本直接套）

1. 0–3 秒钩子：一句核心观点 + 利益，大标题，不要先报功能菜单。
2. 3 个或 4 个章节卡（选题写稿 / 创建数字分身与声音 / 合规辅助检查 / 15 分钟出片或 AI 助理，按最终选题取舍）。
3. 每章 15–25 秒：痛点一句 → 界面证据（录屏或截图+红框）→ 一个可核对的数字或前后对比 → 利益句。
4. 两大模块必须给到「创建数字分身」「创建我的声音」，可用产品预设，界面停留足够看清步骤。
5. 结尾用观众目标收束（「想 15 分钟出一条、还不想露脸的」），点一次「Sphere」，不要点赞关注 CTA；下载引导放到置顶评论。
6. 合规：只说「辅助检查」，不说「保证合规」「100% 不违规」；全程不出现具体产品推荐和收益承诺。

### 7.8 不要从参考片照搬的部分

- 不要用 Codex / Token / GitHub 星标这套程序员语境。
- 不要把片长做成 2 分钟功能展，Sphere 要更短、更财经。
- 参考片是横屏，成片必须按 9:16 重排，不能直接加黑边竖放。
- 参考片结尾没有平台 CTA；Sphere 的 @、话题、置顶评论按 brief 在**发布文案和评论**里完成，不必写进画面主体。
