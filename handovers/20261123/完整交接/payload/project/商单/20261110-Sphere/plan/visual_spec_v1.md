## 0. 一句话诊断

我们把一张 1920 宽的桌面截图，在没有任何上下文的情况下直接放大约 2.5 倍，让它的边缘溢出竖屏，再套一个大红框。

高质量的产品解说正相反，有三层：
1. **先交代「这是哪个软件的哪一页」**，也就是全景。
2. **再把要讲的那一块「拿出来」放大到看得清**，同时保留它在整页里的位置感。
3. **镜头由光标或口播带着走**，每次运动都有缓动、有落点，落定后才出标注。

我们的样片缺了第 1 层。第 2 层用了「暴力裁切」代替。第 3 层是线性平移、没有光标。

## 1. 调研结论（附来源）

### 1.1 建立上下文：全景 → 局部，先回答「我在哪」

- **Guided Zoom**：先给足全景，让观众知道自己在产品的哪里，再推到操作区，讲完拉回再去下一处。这样在手机上既保住空间感，小元素也看得清。（Pixel Studios，[UI Animation for Software Demos](https://www.pixelstudiosinc.com/blog/ui-animation-for-software-demos)）
- 看不清时放大，要让观众「看到自己在哪」时缩回全景，不是每次点击都要放大。（FDM，[Edit a Screen Recording Into a Product Demo](https://fitasticdigitalmedia.com/insights/edit-screen-recording-into-product-demo-video)）
- 自动跟随放大的通病：算法选的局部会把观众需要的整页界面藏起来。产品演示尤其要自己控制留什么在画里。（[DataStudios 评 Screen Studio](https://www.datastudios.org/post/screen-studio-auto-zoom-mechanism-mac-only-limits-and-pricing-explained)）
- Notion Dashboards 发布片（25 秒）用一个连续的虚拟机位：推进到数据库，操作，最后拉回标题，0 个硬切，平均 2.3 秒一拍。（[Cutmap](https://cutmap.co/v/notion-introducing-dashboards)）
- **Progressive Reveal**：复杂页面分步出现，口播说到哪，哪块再出现，观众永远不会「冷启动」面对一整屏。（Pixel Studios，同上）
- **老麦怎么做**：每章第一帧就是产品的「身份页」，例如 Caveman Logo 径向模糊冲入后，紧接 README 英雄区（标题和四个数字卡）。观众先认出是什么，再往下滚到证据（`lm_sheet1.jpg`）。

### 1.2 设备框、浏览器框、背景层次

- 先把应用「装框」：加背景、留边距、圆角、阴影、平滑光标。哪怕不放大，录屏也会显得是「为展示而做」，不像桌面截下来的。（Pane，[Auto Zoom Screen Recorder](https://pane.studio/blog/auto-zoom-screen-recorder-for-saas-founders)）
- FocuSee 和 Screen Studio 这类工具的标准参数是一样的：内边距、圆角、阴影、背景模糊、设备边框。（[FocuSee 用户指南·剪辑](https://focusee.imobie.net/guide/edit-the-recording.htm)，[Screen Studio](https://screen.studio/)）
- Arc 的发布片用倾斜的浏览器窗口、柔和投影，配轻推轻拉营造纵深。Linear 用真实深色 UI，配浅景深虚化无关侧栏。（[Launchscene · Arc Boosts](https://launchscene.app/v/browser-boosts-by-arc)，搜索摘要；[Impractical · Linear Diffs](https://impractical.ai/launch-videos/linear-linear-diffs)）
- 本地参考 `refs2/ark_analysis.md`、`jinmen_alpha_analysis.md`：
  - Alpha Mao 的竖屏版式是「顶部标题栏 + 中间横屏画面 + 底部大字幕」，配大量平移和局部放大。
  - 进门是手机套壳加大字报，好处是看得清，坏处是广告感重。
- **老麦也装框**：0:23 把 Caveman 页面截图做成深底上的卡片，旁边放 ChatGPT 图标（`lm_sheet3.jpg` 中下）。

### 1.3 推镜和平移：动机与时长

- **一镜一个运动**。必须缓入缓出，线性运动看起来很机械。**运动停稳后再出标注**，因为移动中的字读不了。（Lumora，[Camera Moves for UI Videos](https://lumora.video/blog/camera-moves-for-ui-videos)）
- 放大倍数控制在约 **1.5–2×**。再大，小界面会糊，观众也会失去位置感。急推（crash zoom）一次可以，连续五次会晕。（Lumora，同上）
- 后期放大的标准做法：从 100% 平滑到 200%，停在目标区域，讲完回拉。**过渡 0.3–0.5 秒**，太快像跳剪，太慢拖节奏。**每分钟不超过 4–5 次缩放**。超过 3× 明显发虚，除非录制分辨率远高于输出（「录高剪低」）。（屏幕录像站，[录屏局部放大标注技巧](https://lupinshipin.com.cn/articles/zoom-in-recording/)）
- Linear 的手法：
  - 静态 UI 上持续做极轻的漂移（drift），防止画面像卡住。
  - 交互发生处做干脆的推近（punch-in），同时虚化周边。
  - UI 元素用很紧的缓动「啪」地到位。（[Impractical · Linear Diffs](https://impractical.ai/launch-videos/linear-linear-diffs)，[Linear Pulse](https://impractical.ai/launch-videos/linear-pulse)）
- Linear Diffs（52 秒）：16 拍，平均 3.3 秒一拍，0 个硬切，单机位在倾斜窗口上滑行。（[Cutmap](https://cutmap.co/v/linear-introducing-diffs)）
- Screen Studio 的「Focused」动画模式让镜头很快稳定，便于阅读。快速运动加光学运动模糊，看起来像「拍的」，不像「录的」。（[Screen Studio Animations 指南](https://preview.screen.studio/guide/animations)）

### 1.4 标注：标签和引线、光标、聚焦遮罩、计数

- **Spotlight & Dim**：其余区域压暗或模糊，**压暗 40–60%** 通常足够，又不会像坏屏。（Pixel Studios）
- **标签**：3–6 个词，全片一种样式、一种定位逻辑、一种入场动画，下一步之前撤掉。（Pixel Studios）
- 标签用界面上的原词，观众之后能自己找到那个按钮。（FDM）
- **光标**：走干净的弧线，点击前停一下，有可见的点击反馈。也可以干脆不显示光标，让元素自己响应。（Pixel Studios）
- 光标要比笔记本上的大，否则手机上看不见。（[DemoTake](https://demotake.my/blog/vertical-9-16-demo-from-mac-app)）
- 光标平滑、改大小、点击波纹、闲置自动隐藏，都是标配。（Screen Studio）
- 放大区域边缘可加描边框，配合文字标注效果加倍。缩放时可给背景加轻微暗角或模糊。（屏幕录像站）
- **数字**：屏幕上绝不出现录屏里没有的数字。（[ClipMyApp](https://clipmyapp.com/screen-recording-to-tiktok)）
  - 老麦几乎不用跳字计数，数字静态印在界面或字幕里（`laomai_breakdown.md` §6）。
  - 跳动计数只适合「结果在发生」的数据变化。（Pixel Studios）
- **影视飓风式产品标注**：标题、表格、对比和渐进动画建立信息层级。标注线、手绘箭头、局部放大、光标交互突出关键部件。界面保持真实，不虚构控件。（搜索摘要，[B 站 BV1jWonYTEG4](https://www.bilibili.com/video/BV1jWonYTEG4/)；B 站对抓取返回 412，未能打开原视频页）

### 1.5 UI 与动态文字联动

- Linear 片里「字就是旁白」：大、紧、单字重、静止持住，静音观看也能看懂。全片只用三种运动行为，重复本身就是风格。（[Frame24 · How Linear makes launch videos](https://frame24.app/blog/how-linear-makes-launch-videos)）
- Notion 3.0 的手法：
  - AI 输入用打字机动画。
  - 生成过程用 UI 块级联、交错出现，把后台处理「做成看得见的搭建」。
  - 界面镜头之间用动态文字衔接。（[Impractical · Notion 3.0](https://impractical.ai/launch-videos/notion-3)）
- 结果要「停两倍你觉得够的时间」。最常见的失败，是观众还没读完就切走了。（Frame24）

### 1.6 竖屏 9:16 下的界面排版

- **把 16:9 整窗缩进竖屏，只剩一条谁也读不清的窄带**。正确做法：
  - 录窄窗口，让页面重排成单列。
  - 或者靠「跟随放大」，让局部填满竖屏。（[Click & Record](https://clickandrecord.tech/blog/vertical-screen-recording-reels-shorts-tiktok)）
- 三种方案各有代价（DemoTake）：
  - 整窗加黑边：能看全貌，但字读不了。
  - 固定中心裁切：边缘被切掉。
  - 跟随裁切：要有人知道每一刻的焦点在哪。
- 录制前就该做的事：
  - 窗口收窄、字调大。
  - 动作区放在中间、光标调大。
  - 字幕一行几个词，给平台 UI 留位。
  - 在真手机上看导出片。（DemoTake；[Director](https://www.directorscreen.com/guides/record-vertical-screen-video-for-shorts/) 建议浏览器缩放 125–150%）
- **竖屏里标签不小于画高约 4%**。（Pixel Studios）
- 平台 UI 盖住底部和边缘，关键内容放中间。不要靠缩小字号来躲避冲突。（[Recapo · Shorts Safe Zone](https://recapo.ai/blog/youtube-shorts-safe-zone-guide/)）
- Screen Studio 有两种放大：Classic 和 **Loupe（放大镜）**。竖屏改版时，放大会自动重新瞄准。（[Screen Studio](https://screen.studio/)）
  - 放大镜正适合竖屏：上面留全景，下面给细节。

### 1.7 转场

- 同一产品内换状态：Linear 用硬切或 match cut，用空间连续保住方位感。（Impractical）
- 点进详情时让行展开成详情页，不要硬切到新页面。空间转场先回答「我现在在哪」。（Pixel Studios）
- 甩镜（whip pan）是「下面换个地方」，适合发布片的能量感，不适合教程。（Lumora）
- **老麦**：
  - 章内约九成是硬切。
  - 三维翻页只用在**满画幅网页翻到另一张满画幅网页**的时候，所以像「翻到下一页证据」（`lm_sheet1.jpg` 左下）。
  - 我们把翻页用在一块被裁过、漂在黑板上的白卡上，卡边和背景全露出来，所以显得廉价（`g_sheet.png` 右 2 帧）。

### 1.8 每秒信息密度

- 老麦：约 288 汉字/分钟，单镜中位 2.5–3 秒，单镜内每约 1.5 秒有一次变化（红框、切句或滚动），一屏只有 1 个主标记（`laomai_breakdown.md`）。
- 竖屏短视频：每行 3–8 个词，一行停 1.5–3 秒。（ClipMyApp）
- Notion Dashboards 2.3 秒一拍，Linear Diffs 3.3 秒一拍（Cutmap）。
- **本片定额**：
  - 每 0.8–1.5 秒出现 1 个新视觉事件，可以是运动落点、标注或状态变化。
  - 同屏最多 1 个主标注加 1 个标签。
  - 镜头运动和标注不同时进行。

### 1.9 老麦在界面镜头上的具体做法（补充 `laomai_breakdown.md`）

逐帧看 `laomai_frames/` 05–13、17–18、24、27–28、39、42–44：

1. **满画幅、原生像素**：
   - 横屏 1920 的网页截图放进 1920 画布，几乎 1:1，最多推 1.1–1.3×。
   - 清晰度靠原生分辨率，不靠放大。
   - 我们是 DPR1 截图放大 2.5×，所以发软。
2. **页面自带的「身份栏」始终在画面里**：
   - GitHub 顶栏、仓库名、README/Contributing 标签都在。
   - 观众随时知道「这是某个仓库的说明页」。
   - 证据靠**滚动**带到画面中央，不靠裁掉上下文。
3. **红框紧贴单个元素**：
   - 07 帧红框 510×100 px，约占画宽 27%，只框住「Caveman agent · 20 tokens」一个格子。
   - 13 帧红线是表格列和行的描边，不是一个大框。
   - **从不框住半个画面。**
4. **红箭头从空白处指入**（09 帧），不压在内容上。
5. **光标真实可见**，停在被讲的东西旁边（06、17 帧）。
6. **深色时间线界面配黄框标出可替换段**（43 帧）：标记颜色跟着底色换，保证对比。
7. **截图上台当道具**：0:23 页面截图做成深底卡片，配图标对比（14 帧）。1:40 巨型半透明字压在 README 中部（39 帧）。
8. **竖屏没有可照抄的现成解法**：老麦是横屏，能「满画幅原生」。竖屏放不下 16:9 整页，必须换成 §3 的「浏览器框全景 + 放大镜细节」两层结构。这一点是本规范对参考片最大的改编。

## 3. 界面镜头制作规范（可直接照做）

### 3.1 画布与分区（1080×1920，30 fps；界面段内部按 60 fps 渲染再抽 30，减少抖动）

| 区 | y 范围 | 内容 |
|---|---|---|
| 平台顶栏 | 0–150 | 只放背景 |
| 头部信息 | 150–300 | 左：章节标签（见 3.6）。右：免责角标，28 px，60% 白。两者分开放，不挤在一行 |
| 标题区 | 320–500 | 模块标题和动态文字，与 UI 联动 |
| **主舞台** | 520–1160 | 浏览器框（全景或推近都在框内完成） |
| **细节区** | 1190–1490 | 放大镜卡，可选 |
| 字幕 | 1500–1610 | 沿用样片：Noto Sans SC Black 80 px，白字，9 px 黑描边。Fisher 已认可，位置不动 |
| 平台底栏 | 1640–1920 | 只放背景 |
| 左右安全边 | x 60 / 1020 | 任何 UI 和文字不出这条线 |

### 3.2 舞台背景（全片统一，从镜 1 到片尾）

- 底色 `#141418`。
- 粉笔黑板纹理叠 12% 不透明度，和章节卡同一张贴图，这样黑板章节卡进出不会跳。
- 主光：中心 (540, 840)，半径 900 px，`#2C2B36` 径向渐变到透明。
- 暗角：四角 25% 压暗。
- 界面段的背景**不再满屏是黑板**，只留淡纹理，让界面成为唯一的亮主体。

### 3.3 浏览器框（模板 T1）

- 外框：x 60–1020（宽 960），y 520–1160（高 640）。
  - 标题栏 40 px，视口 960×600，比例 16:10，对应录制视口 1440×900 CSS px。
- 标题栏：
  - 底色 `#232329`。
  - 左侧三个圆点，直径 10、间距 8，统一 `#4A4A52`。不用 macOS 彩色，避免苹果联想和视觉噪点。
  - 中间一个标签页：16 px 的 Sphere favicon，加白字 22 px「Sphere · 数字分身」。
  - **不显示地址栏**：域名 `.hk` 会带出地域，Fisher 要求不出现香港。
- 圆角 20 px，1 px 描边 `rgba(255,255,255,0.08)`。
- 阴影两层：`0 40px 90px rgba(0,0,0,0.55)`，`0 10px 24px rgba(0,0,0,0.35)`。
- 可选轻微透视，只在入场 0.4 秒内：`rotateX(6deg)` 到 0，`perspective 1600px`。之后保持正面。
- 框本身全程不动，镜头运动只发生在**视口内容**里（scale 和 translate）。框的边界就是天然的安全裁切边，文字永远不会被画面边缘切掉。

### 3.4 取景级别（scale = 输出 px ÷ 页面 CSS px）

| 级别 | scale | 用途 | 规则 |
|---|---|---|---|
| E 全景 | 0.667 | 1440 宽的整页放进 960 视口，交代「哪个软件、哪一页、有哪些模块」 | 每个新页面或新模块**首次出现必须先 E，持续 ≥0.8 秒**。此时界面字读不清没关系，用标题区大字说明 |
| M 中景 | 1.0–1.15 | 一个弹窗或卡片撑满视口宽，四周留 ≥24 CSS px 页面 | 弹窗必须**整个**在视口内 |
| D 细节 | 2.0–2.4 | 只在细节区放大镜里出现，视口里不做到这么大 | **上限 2.4**。源图必须是 DPR2，等效物理像素放大 ≤1.2× |

硬规则：
1. 任何裁切边离最近的字形 ≥24 CSS px。裁切框吸附到组件边界外扩 16 px。
2. **每段口播里提到的 UI 文字，必须在提到后 0.3 秒内以 ≥32 px 字高出现在画面上**，要么在细节区，要么在 M 级视口里。
3. 不做 scale >1.15 的视口推镜，看细节一律用放大镜。
4. 每 10 秒最多 2 次视口缩放。

### 3.5 镜头运动与缓动

| 令牌 | 曲线 | 时长 | 用途 |
|---|---|---|---|
| `cam` | `cubic-bezier(0.65, 0, 0.35, 1)` | 450–650 ms | 视口推、拉、滑（E↔M） |
| `in` | `cubic-bezier(0.05, 0.7, 0.1, 1)`（Material 3 emphasized decelerate） | 300–400 ms | 元素入场：放大镜、标签、标题 |
| `out` | `cubic-bezier(0.3, 0, 0.8, 0.15)`（M3 emphasized accelerate） | 150–200 ms | 元素离场 |
| `draw` | `cubic-bezier(0.4, 0, 0.2, 1)` | 320 ms | 描边绘制、引线生长 |
| `cursor` | `cubic-bezier(0.45, 0, 0.2, 1)`，走二次贝塞尔弧线，控制点偏离直线 8–12% | 500–800 ms | 光标移动 |
| `drift` | linear | 整段持续 | 停留 ≥1.5 秒时视口 scale +1.5%，防止画面冻住 |

- 运动顺序是固定的：光标先动 → 镜头滞后 100 ms 跟随 → 落定 → 120 ms 后出标注。**运动中不出标注，标注在场时不做运动**，drift 除外。
- 快速运动加方向模糊：速度 >2000 px/s 时，沿运动方向模糊，最大 24 px。用 ffmpeg 帧混合或 CSS 多帧叠加近似。

### 3.6 光标（模板 T5）

- 风格化箭头：白填充加 3 px `#141418` 描边，输出高度 **56 px**。投影 `0 6px 12px rgba(0,0,0,0.45)`。
- 录屏时隐藏系统光标，后期按坐标合成，参照 Screen Studio 的做法。
- 点击：点击前停 250 ms，光标缩到 0.9 再弹回（120 ms）。
  - 同时出现点击波纹：白色 3 px 圆环，直径 0 到 90 px，不透明度 0.7 到 0，300 ms。
  - 配一声短 click。
- 闲置 >0.8 秒淡出（150 ms），下次移动前淡入。

### 3.7 高亮与标注（同屏只允许 1 个主标注）

**A. 聚焦遮罩（默认首选，模板 T4）**
- 视口内目标外的区域压暗：叠 `rgba(10,10,14,0.45)`，在亮界面上约等于亮度降低 40%，并做 2 px 模糊。
- 目标区挖空：圆角 14 px，外扩 12 CSS px。
- 挖空边缘加 2 px `rgba(255,255,255,0.9)` 描边，外加一圈 `0 0 0 6px rgba(255,255,255,0.12)` 光晕。
- 入场 `in` 300 ms，遮罩从 0 到 0.45，挖空框从 1.06 收到 1.0。

**B. 红描边（用于「关键数字或关键词」，每 10 秒 ≤2 次）**
- `#E0000E`，3 px，圆角 12，外扩 8 px，不填充。
- 外加 `0 0 0 5px rgba(224,0,14,0.18)` 光晕和 `0 4px 10px rgba(0,0,0,0.25)` 投影。
- 绘制：从左上顺时针描出（`stroke-dashoffset`），`draw` 320 ms，配 tick。
- **只框单个词或按钮**：框宽 ≤ 视口宽 40%（或放大镜宽 60%）。
- 必须绑定到 UI 坐标：跟随视口变换一起计算，同一个 transform 矩阵。

**C. 标签加引线（标题区或细节区和 UI 的连接）**
- 标签胶囊：`#FFFFFF` 底，`#141418` 字，Noto Sans SC Black 36 px，内边距 12/22，圆角 999。
- 强调版：`#E0000E` 底，白字。
- 引线：2.5 px，`rgba(255,255,255,0.85)`，末端在目标上放 10 px 实心圆点。
- 生长：`draw` 280 ms，先线后标签（标签 `in` 250 ms，延迟 120 ms）。
- 文字 3–6 个字，**用界面上的原词**，例如「手机上传」「开始录制」。

**D. 放大镜卡（竖屏核心解法，模板 T3）**
- 位置：细节区 x 60–1020，y 1190–1490（960×300）。高度可按内容在 240–360 之间取。
- 圆角 18，2 px `rgba(255,255,255,0.14)` 描边，阴影同浏览器框。
- 内容是 DPR2 源图的对应区域，scale 2.0–2.4，字高 ≥32 px。
- 两条连接引线：从视口里的源区域（同时显示 2 px 白色虚线框）的两个下角，连到放大镜卡的两个上角。1.5 px，`rgba(255,255,255,0.35)`，`draw` 250 ms。观众一眼看出「下面是上面那一块放大」。
- 卡内平移：换细节时卡内容 `cam` 400 ms 滑动，源区域虚线框同步移动。
- 卡左上可放卡头标签：24 px 白字 70%，内容是原 UI 区块名，如「照片要求」。

**E. 数字**
- 只用界面上真实存在的数字（「15秒」「15」「14」）。
- 静态大字为主。
- 若做计数，只在数字第一次出现时从 0 跳到目标值，500 ms，`in` 曲线，全片 ≤2 次。

### 3.8 UI 与动态文字联动（模板 T7）

- 标题区 y 320–500 只放两类字：
  1. **模块标题**：「模块①」红胶囊 32 px，后接白字 64 px「创建数字分身」。模块切换时纵向遮罩滚动替换，250 ms。
  2. **步骤短语**：40 px 白 85%，例如「① 上传 1 张照片 → ② 生成形象」。当前步骤全白，其余 40%。口播进到哪一步，哪一步点亮。
- 标题区的字和 UI 的连接：关键时刻用 3.7C 的引线把标题短语连到 UI 元素。每镜最多 1 次。
- 字幕说的词，画面上必须同时能找到它，可以是 UI 原文或放大镜。

### 3.9 转场

| 场合 | 用什么 | 参数 |
|---|---|---|
| 图卡或章节卡 → 界面 | 冲入（zoom-through） | 前一镜 scale 1→1.25，加径向模糊 0→20，0.3 秒。浏览器框 1.12→1.0，模糊 20→0，0.35 秒。whoosh |
| 同一页内换焦点 | **不切**，用视口镜头运动（`cam`）连续过去 | 先拉回 E，再推向新焦点，或直接平滑滑过去 |
| 打开或关闭弹窗 | 产品自身的弹窗动效：遮罩淡入，弹窗 0.96→1，200 ms，配合视口 E→M 推近 | 与光标点击同步 |
| 同章换另一个页面 | 甩镜：视口内容沿 x 方向 ±1200 px 位移，300 ms，`cubic-bezier(0.7,0,0.3,1)`，中段 24 px 方向模糊。浏览器框不动，标签页文字同时切换 | whoosh 短 |
| 章节之间 | 硬切到章节卡 | hit |
| **禁止** | 三维翻页、交叉溶解、闪白（钩子除外） | — |

### 3.10 图卡（痛点卡、对比卡，模板 T8）

- 主体占画面面积 ≥35%，即至少约 900×800 的视觉块。图标描边 ≥10 px，粉笔质感。
- 每个图标下配 56 px 白字标签。
- 每 0.8–1.2 秒一个事件。整卡 drift +3%。

### 3.11 隐私与合规遮挡

- **在源图（DPR2 PNG）上先做遮挡，再进合成**。不要在裁切后的画面上补。
- 遮挡样式：毛玻璃块。
  - 源区域高斯模糊 24 px，叠 `rgba(255,255,255,0.55)`。
  - 中间放一行 28 px 灰字，说明被遮的是什么，例如「朗读示例文本（约 15 秒）」。
  - 这样看起来是刻意的设计，不是坏帧。
- 需遮挡的内容：
  - 朗读文本整段（含「香港」）。
  - 账号头像和昵称。
  - 示例照片的城市天际线：做 12 px 模糊，或在 M 级视口里不让它超过 120 px 宽，见 §6 待定。
- 导出后逐帧 OCR 或人工检查「香港」「维港」「中环」。**包括运动模糊帧**，转场中段最容易漏。

### 3.12 声音配合

- 标注描边：tick（-24 dB）。
- 光标点击：click（-22 dB）。
- 冲入：whoosh。
- 甩镜：短 whoosh（-20 dB）。
- 每秒最多 1 个 SFX。

### 3.13 验收（每版导出前跑）

1. 每 0.5 秒抽帧，接触表人工过一遍。逐项检查：
   - 有没有文字被画面或框裁半？
   - 每个新页面首帧是不是 E 级？
   - 同屏主标注是否 ≤1？
2. 运动段抽 1/30 秒帧，确认标注只在运动停稳后出现，且和 UI 对齐。
3. 放大镜内字高抽测 ≥32 px（取汉字外接框高度）。
4. 隐私词逐帧检查，转场帧单独查一遍。
5. 用手机全屏实看一遍，确认最小的被讲到的字能读。

## 5. 需要补录的素材

### 5.1 通用设置（所有素材一致，换场景才能无缝）

- **视口 1440×900 CSS px，DPR 2**，输出 2880×1800 PNG。
  - 用 Chrome 自带 DevTools 的设备工具栏：Responsive，1440×900，DPR 2，再用 ⋮ → Capture screenshot。
  - 不装软件。
  - 1440 宽比 1920 少 25% 空白，分身页的内容列在画里更饱满。先确认 1440 下布局不塌；塌了就用 1600×1000。
- 界面语言用产品自带的简体中文。不用浏览器翻译。
- 无 hover tooltip、无 toast、无加载骨架、图片加载完成后再截。
- 隐藏书签栏和扩展，账号头像和昵称后期遮挡。
- **不上传照片、不勾承诺框、不点「开始录制」**。
- 每个状态截 2 张，防偶发。
- 动效参考视频（可选）：x11grab 60 fps 录一遍弹窗开关，只用来量产品自己的动画时长和曲线，不进成片。
